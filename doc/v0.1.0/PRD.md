# True North v0.1.0 PRD

> 版本定位：对齐 `packages/product-wiki/wiki` 现有设计，交付基础可用的 Growth 套件 (Goal / Task / Todo / Habit) 以及共用交互骨架。本 PRD 仅描述 v0.1.0 范围，后续增量功能在模块级 PRD/TDD 中扩展。

---

## 1. 背景与目标

| 项目背景                                                                                  | 核心目标                                                                                              |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| True North 需要一个落地可用的 MVP，将 ProductWiki 中的多级联动蓝图转化为真实的 Web 体验。 | 1) 打通 Goal→Task→Todo 的核心链路；2) 统一交互/视觉规范，确保后续可扩展；3) 保持与 ProductWiki 一致。 |

关键约束：

1. **目标状态仅以 Tag 展示**（来自用户最新确认），禁止状态切换下拉。
2. **“已完成”按钮放置在右侧操作区**（详情面板右上角，与“编辑/删除/放弃”同区域）。
3. **右上角提供 `...` 按钮**，点击后弹出下拉菜单，包含“编辑 / 删除 / 放弃”三项。

## 2. 用户与场景

| 角色              | 需求                               | 场景                                                        |
| ----------------- | ---------------------------------- | ----------------------------------------------------------- |
| 个人规划者        | 需要拆解长期目标，查看层级关系     | 在 `goal-tree` 中创建/浏览目标树                            |
| 执行者            | 需要跟踪任务、待办、习惯的执行情况 | 通过 `task-week`、`todo-today`、`habit-list` 打卡或更新状态 |
| 管理者/自我复盘者 | 需要查看整体进度与健康度           | 使用统计页（Todo Dashboard、Habit Statistics）              |

| 模块 | 范围                                                              |

## 4. 详细需求

### 4.1 Goal 模块

#### 4.1.1 目标树视图

1. 右侧 `GoalMain`：
   - 顶部显示目标名称、状态 Tag（不可编辑）、目标信息；
   - “已完成”按钮位于右上角操作区，按钮风格为主要按钮；
   - 右上角 `...` Dropdown，菜单项：编辑、删除、放弃；
   - 详情 Tab：概览 / 子目标 / 关联任务。
2. 状态展示：
   - 仅显示 Tag，无状态切换控件；
   - 状态颜色沿用 ProductWiki（灰/蓝/绿/橙/描边灰）。

#### 4.1.2 目标操作逻辑

| 操作     | 入口         | 行为                           | 校验                            |
| -------- | ------------ | ------------------------------ | ------------------------------- |
| 编辑     | `...` 菜单   | 打开右侧抽屉，内联编辑         | 时间/重要度继承校验             |
| 删除     | `...` 菜单   | 二次确认后删除                 | 禁止删除有子目标/关联实体的目标 |
| 放弃     | `...` 菜单   | 状态置为“放弃”                 | 提示用户影响                    |
| 标记完成 | “已完成”按钮 | 状态设为“已完成”，触发级联提示 | 提供撤销入口                    |

### 4.2 Task 模块

| 视图 | 需求要点 |
| --- | --- |
| 今日 / 本周 | 按执行分组展示任务；点击任务打开详情抽屉，可直接完成或开始专注。 |
| 日历 / 全部 / 统计 | 按计划日期、组合筛选或状态统计查看任务；所有详情入口均打开同一抽屉。 |

#### 4.2.1 Task 详情抽屉

1. **入口与容器**：任务页各视图及 Goal 详情的关联任务均在当前页面打开详情抽屉；不新增独立路由或返回状态缓存。
2. **左侧任务树**：抽屉只展示当前任务所属根任务及其全部后代；选中任务时展开父链。子任务在该区域内联创建，并继承父任务的计划范围、重要度与难度。
3. **右侧详情**：顶部为只读状态 Tag、`...` 菜单（编辑、删除、放弃）和“标记完成/恢复”主按钮；Tab 固定为“概览 / 关联 Todo / TrackTime”。
4. **关联能力**：关联 Todo 在抽屉内查看并打开其编辑抽屉；TrackTime 仅打开全局计时器并携带当前任务，不自动开始计时。

### 4.3 Todo 模块

参见 ProductWiki · `growth.todo` 状态字段、`growth.todo.rule.focus-range-only`。

1. **状态集合**：`todo`（待开始）/ `done`（已完成）/ `abandoned`（已放弃）。删除 `in_progress`；不再提供「开始 / 暂停」操作。
2. **完成与放弃**：未完成待办可完成或放弃；已完成/已放弃可恢复为待开始。计时结束**不**改变待办状态。
3. **专注关联**：
   - 未完成且计划开始时间 ≠ 结束时间（区间）：列表与详情可「开始专注」，打开全局计时器并预关联该待办，不自动开始计时。
   - 计划开始时间 = 结束时间（时间点）：隐藏待办入口上的计时管理；若已有关联专注记录，详情中仍可只读查看。
4. **验收**：
   - 界面无「开始」状态操作、无「进行中」筛选/标签。
   - 区间未完成待办可关联专注并落库；结束后待办仍为 `todo`（除非用户另行完成）。
   - 时间点待办无专注入口，历史记录可读。

### 4.4 TrackTime 与待办

参见 ProductWiki · `growth.track-time.rule.todo-optional`、`growth.track-time.rule.todo-range-focus`。

1. 专注记录可关联任务或待办（互斥），也可无关联。
2. 顶栏唤起时提供可搜索的任务与待办联合选择；从任务或待办入口唤起时锁定预填关联，不可切换。
3. 服务端不因时间点计划拒绝创建关联待办的记录；产品约束落在待办入口。

## 5. 交互与视觉规范

| 元素       | 规范                                                           | 备注               |
| ---------- | -------------------------------------------------------------- | ------------------ |
| 状态 Tag   | 仅展示，无切换；颜色参照 ProductWiki design tokens             |                    |
| 右侧操作区 | 从左到右：状态 Tag、`...` 下拉、主要按钮（如“已完成”或“恢复”） |                    |
| Dropdown   | 采用 `@sue/design-web-react` `Dropdown`，菜单项：编辑、删除、放弃（Goal） | 删除操作需加危险色 |
| 按钮       | 主要按钮用于完成/保存，次要/文字按钮用于辅助操作               |                    |
